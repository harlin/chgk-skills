# План скилла chgk-candle

Статус: план принят владельцем 2026-11-19 с предложенными решениями; первая версия скилла — `plugins/chgk-editor/skills/chgk-candle/`. Синтаксис поиска проверен, см. `references/search.md` скилла.

## Задача

Проверить вопрос на свечку по базе gotquestions.online: найти опубликованные вопросы с той же идеей и решить, помогает ли знание старого вопроса взять новый. Сейчас chgk-assess и chgk-improve проверяют свечку только по памяти и выдают автору поисковые запросы. Новый скилл сам выполняет эти запросы, если автор разрешил, и разбирает найденное.

Вход: вопрос (обычно несыгранный), его ответ и, если есть, находка из chgk-improve.
Выход: список найденных вопросов-предшественников с вердиктом по каждому и общий вывод.

## Что известно о поиске (проверено 2026-11-19, один запрос)

- `https://gotquestions.online/search?search=<запрос>` отдаёт 200 без challenge-страницы. Страница рендерится на сервере, как и страницы вопросов (см. `docs/gotquestions-fetching.md` в приватном репозитории).
- Результаты лежат в RSC-пейлоаде `self.__next_f.push(...)` под ключом `"initialData"`: `{questions, highlights, total, page, pageSize, totalPages}`.
- `pageSize` = 18. На запрос «тест» нашлось 7712 вопросов на 429 страницах.
- Каждый элемент `questions` — полный объект вопроса: текст, ответ, зачёт, комментарий, источники, `complexity` (процент взятия), авторы. В `tour.pack` есть название пакета, `startDate` и `endDate`. Отдельный запрос на каждый вопрос не нужен.
- `highlights[<id>]` показывает, в каком поле совпадение (`answer`, `zachet`, `comment`, …), с `<span class="hl">`. Поиск учитывает словоформы: «тест» нашёл «Тесты ДНК».
- Порядок выдачи — по релевантности, не по дате.

Ещё не проверено (каждое — отдельный запрос, не чаще раза в минуту):
- как работают запросы из нескольких слов: И, ИЛИ или фраза; работают ли кавычки и минус;
- есть ли параметры фильтра (по полю, по дате, по типу пакета);
- ищет ли поиск по тексту раздатки;
- как сайт отвечает на пустую выдачу.

## Порядок работы

1. **Ключи.** Из вопроса выписать 3–5 ключей — то, по чему предшественник найдётся, даже если он написан другими словами:
   - ответ и его зачётные формы;
   - редкие имена и реалии: основы слов и варианты транслитерации (Бакленд / Баклэнд, Гёте / Гете, Хемингуэй / Хэмингуэй), оригинальное написание;
   - находку двумя-тремя словами.

   Пары «ответ + реалия» сужают выдачу, если поиск понимает И.
2. **Согласие.** Показать автору список запросов и ждать «да». Без согласия не отправлять ничего (см. «Конфиденциальность»).
3. **Поиск.** По одному запросу в минуту, только первая страница выдачи. Следующие страницы — по просьбе автора или если в первой странице есть хотя бы одно попадание, а `totalPages` невелико.
4. **Отбор.** Из выдачи взять вопросы, где совпадает ответ или ключевая реалия. Остальное отбросить, не показывая.
5. **Вердикт по каждому кандидату:**
   - **свечка** — та же находка ведёт к тому же ответу, и знание старого вопроса помогает взять новый;
   - **частичная** — та же реалия, но другой ход или другой ответ; помогает лишь отчасти;
   - **тема** — та же тема, взять не помогает. Это не блокер.

   Для каждого кандидата: пакет, дата, процент взятия (`complexity`), ссылка, одна фраза о том, что совпало.
6. **Вывод.** Насколько это серьёзно. Учитываются давность, масштаб турнира (синхрон или локальный), степень совпадения и взятие старого вопроса: если старый почти никто не взял, его мало кто помнит. Если свечка есть, предложить ходы из `chgk-improve/references/moves.md`: «Сменить повод», «Заменить второй факт», «Другой угол».
7. **Чего не нашли.** Явно сказать, что поиск не доказывает отсутствия свечки. Сайт не покрывает всю базу, а поиск по словам не находит пересказ другими словами. Назвать запросы, которые автор может прогнать сам на db.chgk.info.

## Конфиденциальность

Скилл существует ради несыгранных вопросов, поэтому правило «не отправлять текст несыгранного вопроса во внешние сервисы» здесь смягчается, но не отменяется:
- отправляются только короткие ключевые запросы (1–3 слова), никогда текст вопроса и никогда фраза из него;
- список запросов автор подтверждает до отправки;
- ответ отдельным запросом отправляется только вместе с подтверждением автора, что так можно. Ответ в паре с реалией выдаёт больше, чем каждый ключ по отдельности.

## Вежливость к сайту

Те же правила, что в `docs/gotquestions-fetching.md`:
- не чаще одного запроса в минуту, с общим файлом состояния для всех наших инструментов (например, `~/.cache/chgk-skills/gq_last_request.sqlite`), чтобы скилл и `gq_fetch.py` не обгоняли друг друга;
- честный User-Agent;
- при любом не-200 ответе или challenge-странице — стоп без повтора, и автору остаются запросы для ручной проверки;
- результаты кешировать локально по тексту запроса, чтобы повторная проверка не ходила на сайт.

Типичная проверка — 3–5 запросов, то есть 3–5 минут. Скрипт идёт в фоне, а скилл говорит автору, сколько ждать.

## Состав

- `plugins/chgk-editor/skills/chgk-candle/SKILL.md` — порядок работы, вердикты, формат ответа.
- `plugins/chgk-editor/skills/chgk-candle/scripts/gq_search.py` — только стандартная библиотека Python:
  - запрос → JSON с вопросами текущей страницы и полями `total` и `totalPages`;
  - соблюдает лимит и общий файл состояния, кеширует выдачу;
  - останавливается на «стене».

  Код разбора пейлоада такой же, как в `gq_fetch.py`: вынести общий кусок или скопировать.
- Правки в chgk-assess (шаг 4) и chgk-improve (подготовка, «Что проверить автору»): «если автор согласен на поиск — вызови chgk-candle, иначе как сейчас».

## Проверка

Евалы — в приватном репозитории и только на сыгранных вопросах. Наборы:
- **известные пары свечек** — вопрос и его предшественник в базе; на поиске «тест» уже видна пара 219347 / 207253 о Бакленде;
- **отрицательные примеры** — вопросы, у которых по теме есть соседи, но свечки нет;
- **вопросы с редкой транслитерацией**, чтобы проверить, что ключи покрывают варианты написания.

Метрики:
- найден ли предшественник;
- верен ли вердикт;
- сколько запросов на это ушло.

## Решения

1. **Название:** `chgk-candle`. Возможные альтернативы — `chgk-svechka` и `chgk-repeat-check`.
2. **Подтверждение запросов:** одним списком перед отправкой (предложение) или без подтверждения, если автор заранее разрешил в сессии.
3. **Отправлять ли ответ отдельным запросом:** по умолчанию да, но только после согласия (предложение).
4. **Глубина:** только первая страница каждого запроса (предложение); вторая — по просьбе.
5. **db.chgk.info:** пока не трогаем. Это второй источник с другим покрытием; добавить позже, отдельно изучив его правила.
6. **Где живёт скрипт:** в публичном плагине рядом со скиллом (предложение). `gq_fetch.py` остаётся в приватном репозитории для калибровки.
